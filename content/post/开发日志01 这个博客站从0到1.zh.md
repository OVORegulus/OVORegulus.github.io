## 目标

一句话：**能长期写下去的个人站**。因此几个硬性要求：

- 内容必须是纯文本（Markdown），不能被某个平台锁死
- 部署要免费、要自动，推代码就上线
- 打开速度要快，最好没有数据库和后台

## 技术选型

| 部分 | 选择 | 为什么 |
| --- | --- | --- |
| 生成器 | Hugo（extended） | 单文件可执行程序，构建几百毫秒，不用装运行时 |
| 主题 | Stack | 卡片式布局，自带暗色模式和目录，够用 |
| 托管 | GitHub Pages | 免费，和仓库天然打通 |
| 部署 | GitHub Actions | push 即发布，不用本地构建 |

被排除的方案：WordPress（要服务器和数据库，维护成本高）、各类在线笔记（不能自定义样式，数据不在自己手里）。

## 目录结构

Hugo 的约定很清晰，记住这几个就够：

```text
blog/
├── config/_default/     # 配置：hugo / params / menu / languages
├── content/
│   ├── post/            # 文章（单文件 xxx.md，或 xxx/index.md）
│   ├── categories/      # 专栏定义
│   └── page/            # 独立页面：关于、归档、链接
├── layouts/             # 覆盖主题模板（不改主题本体）
├── assets/              # 会被处理的资源：scss、icons、图片
└── static/              # 原样拷贝的文件
```

**关键约定**：`layouts/` 和 `assets/` 里放同名文件就能覆盖主题的版本。这样主题可以作为 git submodule 保持干净升级，自己的改动全在项目目录里。

## 踩过的坑

### 1. 配置文件被「顶掉」了

项目根目录放了一个 `hugo.toml`，同时又有一套 `config/_default/`。结果：**Hugo 只会读根目录那个**，`config/_default/` 下的 `params.toml`、`menu.toml` 全部失效，页脚显示的是主题默认值。

教训：一个 Hugo 站点只用一种配置方式，不要两种并存。

### 2. 文章目录写错会绕过永久链接

`content/post/xxx/index.md` 里的 `index.md` 是**页面**，会套用 `[permalinks]` 的 `post = "/p/:slug/"`。

但如果写成 `_index.md`，它就成了**栏目（section）**，URL 变成 `/post/xxx/`，永久链接规则根本不参与。一个下划线的差别，输出路径完全不同。

### 3. 多余的语言文件会生成野页面

主题示例内容里带着 `_index.ja.md`、`index.zh-hant-tw.md` 这类多语言变体。如果站点其实只做中文，这些文件会被 Hugo 当成**普通内容页**渲染，菜单被污染、还会生成 `/_index.ja/` 这种空白页并被 sitemap 收录。

## 复盘

**最省时间的一个决定**：选 Hugo 而不是需要常驻服务的方案。构建 0.5 秒、产物是纯静态文件，改完推上去就行，没有任何运维负担。

**最后悔的一个决定**：一开始在根目录和 `config/_default/` 里同时写配置，排查了半天「为什么配置不生效」。
